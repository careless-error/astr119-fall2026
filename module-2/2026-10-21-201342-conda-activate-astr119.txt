❯ why does the loop  start at 0 and go to n-1 instead of n                      

⏺ It actually starts at k = 1, not 0. The reason for both ends is that each pass
  computes the next polynomial, P_{k+1}, not P_k.

  Why start at 1: you already have P₀ and P₁ before the loop. The first pass
  uses k = 1 to build P₂ from P₁ and P₀.

  Why stop at n−1: the last pass needs to produce Pₙ. Since a pass makes
  P_{k+1}, that means k + 1 = n, so the last k is n − 1. Going one more pass to
  k = n would compute P_{n+1}, which is one too far.

  Example with n = 4:

  ┌─────┬────────┬───────┐
  │  k  │  uses  │ makes │
  ├─────┼────────┼───────┤
  │ 1   │ P₁, P₀ │ P₂    │
  ├─────┼────────┼───────┤
  │ 2   │ P₂, P₁ │ P₃    │
  ├─────┼────────┼───────┤
  │ 3   │ P₃, P₂ │ P₄ ✓  │
  └─────┴────────┴───────┘

  The loop runs 3 times, which is n − 1. In Python, range(1, n) gives exactly 1,
  2, …, n−1.
