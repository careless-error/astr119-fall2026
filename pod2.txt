⏺ The program prints 2 and then ['Earth', 'Mars']. Both functions change
  something defined outside them, but they do it in different ways, and that's
  why only one of them needs global.

  The rule: if a function contains an assignment like x = ... anywhere in its
  body, Python treats x as a local name throughout that function, unless you
  declare it global.

  bump() (lines 6–8)

  count = count + 1 is an assignment to the name count. That assignment would
  make count local to bump. Line 7, global count, tells Python to use the
  module-level count instead. Each call reads the global value, adds 1, and
  rebinds the global name to the new integer. Two calls take it 0 → 1 → 2.

  add_mars() (lines 11–12)

  There is no assignment here. names is never on the left of an =. Python looks
  up names, doesn't find it locally, and finds the global list. .append('Mars')
  then modifies that list object in place. The name names still refers to the
  same list, and that list now holds two items. A function can change a mutable
  object (list, dict, array) through a global name without global. It only needs
  global to make the name point to a different object.

  The trap

  Try deleting line 7 in your head. Then count = count + 1 makes count local,
  and Python tries to read the local count on the right side before anything has
  been assigned to it. You get UnboundLocalError. Integers can't be changed in
  place, so the only way to "change" count is to rebind the name. That's why it
  needs global and the list doesn't.
